# Human Test Checklist: portable path key, batch planner, and the tree copy's link choice

**Target version:** 0.5.0
**Ships with commit:** `v0.5.0: portable path key, batch planner, and a tree copy that keeps junctions`
**Companion automated tests:** 90 new tests -- `tests/test_portable.py` (53), `tests/test_batch_layout.py` (23), `tests/test_paths_expand.py` (6), `tests/test_copy_tree_links.py` (8) -- plus 16 new rows in `tests/test_import_stability.py`.

## What this is

A hand-run pass over what 0.5.0 adds, for a maintainer or an outside tester. The automated tests compute paths and copy small trees inside pytest's temp folder; this checklist covers what they cannot construct: a second drive, a real network share, an account without the symlink privilege, WSL reading a Windows drive, and the tools that already import this package.

filekit is a library, so every step is a Python script or a one-line `python -c`. The scripts live in `tests/one-offs/` and are the same command in every shell.

## Prerequisites

1. Python 3.8 or later with this checkout importable (`pip install -e .`, or set `PYTHONPATH` to the checkout).
2. Run from the repository root.
3. **Scratch folder:** every step that writes takes the name of a NEW folder and refuses one that exists. Pick a location you can throw away. Nothing in this checklist deletes anything; remove the scratch folders yourself at the end (see Cleanup).
4. Sections are independent. To repeat one, use a new scratch folder name.

Confirm the version first (same in every shell):

```
python -c "import dazzle_filekit; print(dazzle_filekit.__version__)"
```

Expected: `0.5.0`.

## High-Value Verification (~5 minutes)

### HV.1 -- The documented examples are true

Validates: every example in the 0.5.0 section of the API reference.

- [ ] **Steps** (same in every shell):

  ```
  python tests/one-offs/probe_doc_examples_v050.py
  ```
- [ ] **Expected:** ten lines starting `ok`, then `10 of 10 match`.
- [ ] **Why this matters:** these are the lines a new user copies; a `DIFF` means the page and the code disagree.

### HV.2 -- A junction (or symlink) is kept, followed, or skipped as asked

Validates: `copy_tree_preserving_links(links=...)`, including the changed default.

- [ ] **Steps** (same in every shell; choose a folder name that does not exist):

  ```
  python tests/one-offs/checklist_v050_links.py <new scratch folder>
  ```
- [ ] **Expected:**
  - `links='keep'` -- a `junction ->` (Windows) or `symlink ->` line naming the same target as the source link
  - `links='follow'` -- `folder holding ['behind-the-link.txt']`
  - `links='skip'` -- `absent`
  - `outside still holds: ['behind-the-link.txt']`
- [ ] **Check:** open `<scratch>/copy-keep/sub/`. It holds `inside.txt` and a link, and no second copy of `behind-the-link.txt` exists under `copy-keep`.
- [ ] **Why this matters:** before 0.5.0 the default copied everything behind a junction. A tool that copies a tree and then removes the original depends on this.

### HV.3 -- One file has one key from Windows and from WSL

Validates: the key is runtime-neutral.

- [ ] **Steps** (same in every shell):

  ```
  python -c "from dazzle_filekit import encode_portable_path as e; print(e('C:/Users/x/a.txt', flavor='windows') == e('/mnt/c/Users/x/a.txt', flavor='wsl'), e('/mnt/c/Users/x/a.txt', flavor='posix'))"
  ```
- [ ] **Expected:** `True ROOT/mnt/c/Users/x/a.txt`
- [ ] **Why this matters:** a store written from Windows must be readable from WSL, and plain Linux must not mistake `/mnt/c` for a drive.

### HV.4 -- Two same-named folders get different places

Validates: the planner never returns one stored path twice.

- [ ] **Steps** (same in every shell):

  ```
  python -c "from dazzle_filekit import plan_batch as p; r = p(['C:/proj/a/docs', 'C:/proj/b/docs', 'E:/other/docs'], flavor='windows'); print(r.ok, [i.relpath for i in r.items], [b['key'] for b in r.bases])"
  ```
- [ ] **Expected:** `True ['0/a/docs', '0/b/docs', '1/docs'] ['C/proj', 'E/other']`
- [ ] **Why this matters:** this is the collision that the planner exists to remove; three items named `docs` must land in three places.

### HV.5 -- The tools that already import filekit still start

Validates: the package's top-level import, which other tools load at start-up.

- [ ] **Steps** (only where dazzlecmd is installed; same in every shell):

  ```
  dz safedel status
  dz fixpath --help
  ```
- [ ] **Expected:** each prints its normal output; no traceback.
- [ ] **Why this matters:** `dazzle_filekit/__init__.py` gained imports; an error there breaks every consumer at once.

## Section 1: The portable key

### 1.1 Paths with no portable form are refused, not guessed

- [ ] **Steps** (same in every shell):

  ```
  python -c "from dazzle_filekit import encode_portable_path as e, PortablePathError as P
for p in ['relative/path', 'C:drive-relative', 'C:/../x']:
    try: print(p, '->', e(p, flavor='windows'))
    except P as x: print(p, '-> refused:', x)"
  ```

  In cmd.exe, which cannot pass a multi-line `-c`, save the three lines after `python -c "` to a file and run that file.
- [ ] **Expected:** three `refused:` lines, each naming the path and the reason in plain words.
- [ ] **Check:** is each message clear enough to act on without reading the source?

### 1.2 A real network share (needs one)

- [ ] **Steps:** replace `\\server\share\folder` with a share you can reach, and run:

  ```
  python -c "from dazzle_filekit import encode_portable_path as e, decode_portable_path as d; k = e(r'\\server\share\folder', flavor='windows'); print(k, d(k, runtime='windows'))"
  ```

  In bash, single-quote the whole `-c` argument instead and keep the `r'...'` string as written.
- [ ] **Expected:** `UNC/server/share/folder \\server\share\folder` with your names.
- [ ] **Check:** a mapped drive letter for the same share gives a DIFFERENT key (`Z/folder`). That is by design -- the key names the path as written, and nothing is looked up -- but note whether it surprises you.

### 1.3 Flavor is required

- [ ] **Steps** (same in every shell):

  ```
  python -c "from dazzle_filekit import encode_portable_path as e; e('C:/x')"
  ```
- [ ] **Expected:** a `TypeError` naming the missing `flavor` argument.

## Section 2: The planner

### 2.1 Duplicates and nested items

- [ ] **Steps** (same in every shell):

  ```
  python -c "from dazzle_filekit import plan_batch as p; r = p(['C:/a/x', 'c:/A/X', 'C:/a/x/inner', 'C:/a/y'], flavor='windows'); print(r.ok, [i.relpath for i in r.items]); print(r.warnings)"
  ```
- [ ] **Expected:** `True ['x', 'y']`, and two warnings: one for the duplicate, one for the item inside another.
- [ ] **Check:** do the warnings say which path was merged or dropped, and why?

### 2.2 Two POSIX items that differ only in case are refused, not merged

- [ ] **Steps** (same in every shell):

  ```
  python -c "from dazzle_filekit import plan_batch as p; r = p(['/srv/a/Docs', '/srv/a/docs'], flavor='posix'); print(r.ok, r.errors)"
  ```
- [ ] **Expected:** `False ["'/srv/a/docs' and '/srv/a/Docs' would both be stored at 'docs'"]`
- [ ] **Why:** on POSIX these are two different folders, so they are not merged as duplicates. But a store may sit on a filesystem that ignores case, where the two would overwrite each other, so stored paths are always compared without regard to case and the plan reports the clash.
- [ ] **Check:** is "refuse" the outcome you would want here, or would a renamed second item serve better? Note your view; the behaviour is deliberate but worth a second opinion.

## Section 3: Taking a path literally

### 3.1 `expand=False` never aims at the home folder

- [ ] **Steps** (same in every shell; run from any folder):

  ```
  python -c "from dazzle_filekit.paths import normalize_cross_platform_path as n; print(n('~')); print(n('~', expand=False))"
  ```
- [ ] **Expected:** the first line is your home folder; the second is a path ending in `~` under the current folder.
- [ ] **Why it matters:** a deletion tool handed a folder literally named `~` must not expand it.

## Section 4: Links in a copied tree

### 4.1 An account without the symlink privilege (Windows, non-elevated, Developer Mode off)

- [ ] **Steps:** run HV.2 from such an account.
- [ ] **Expected:** identical to HV.2. Junctions need no privilege, so `keep` must still produce a junction.

### 4.2 Across drives (needs a second drive)

- [ ] **Steps:** create the HV.2 scratch folder on one drive, then copy its `src` to another drive:

  ```
  python -c "from dazzle_filekit.operations import copy_tree_preserving_links as c; c(r'<scratch>\src', r'<other drive>:\fk050-cross')"
  ```
- [ ] **Expected:** `<other drive>:\fk050-cross\sub\link` is a junction pointing back at `<scratch>\outside` on the first drive, and opening it shows `behind-the-link.txt`.
- [ ] **Check:** `<other drive>:\fk050-cross` holds no copy of `behind-the-link.txt` of its own.

### 4.3 WSL reading a Windows drive

- [ ] **Steps:** from WSL, in the checkout under `/mnt/<drive>/...`, run HV.1 and HV.2 (the scratch folder under `/tmp`).
- [ ] **Expected:** HV.1 `10 of 10 match`; HV.2 reports `symlink ->` lines for the source and for `keep`.

## Section 5: The two 0.5.1 fixes

### 5.1 The package loads without unctools, and an extended network path stays a network path

- [ ] **Steps** (same in every shell):

  ```
  python tests/one-offs/probe_advisor_claims_v050.py
  ```
- [ ] **Expected:**
  - `1a` -- `import ok; unctools imported: False`
  - `1b` -- `unctools loaded by a plain import: False`
  - `2` -- the first line ends in `'\\\\srv\\share\\a'` (a network path), not a path under the folder you ran it from
- [ ] **Why this matters:** before 0.5.1 the first failed with an import error, and the second produced a folder path under the current directory -- on the code path a deletion tool uses to read its targets.

### 5.2 On a machine where unctools really is not installed (needs one)

- [ ] **Steps:** in a fresh virtual environment, install filekit with `pip install --no-deps .` plus `dazzle-lib`, then run `python -c "import dazzle_filekit; print(dazzle_filekit.encode_portable_path('C:/a', flavor='windows'))"`.
- [ ] **Expected:** `C/a`. Encoding a `\\server\share\x` path there raises an `ImportError` naming unctools; that is expected, since UNC parsing is unctools' job.

## What the automated tests DON'T cover

- A real second drive: the tests copy within one temp folder (4.2).
- A real network share: UNC paths are only computed, never opened (1.2).
- An account that cannot create symlinks: the symlink test skips there, and nothing checks that the skip is the only difference (4.1).
- WSL against `/mnt/<drive>` (4.3).
- Whether the refusal and warning messages are clear to a person (1.1, 2.1).
- The consumers: dazzlecmd and safedel are separate projects with their own suites (HV.5).
- Very large trees and trees with many junctions: no timing is measured.

## Reporting issues found

1. Note the section and step number.
2. Capture the exact command and its output.
3. Keep the scratch folder if the step wrote one.
4. File an issue that names this checklist and the version.

## Cleanup

The checklist deletes nothing. Remove each scratch folder you created (HV.2, 4.2, 4.3). They contain junctions or symlinks, so use a tool that removes a link without following it. The link's target, `outside`, is inside the same scratch folder in every step, so nothing beyond the scratch folder is at stake.
