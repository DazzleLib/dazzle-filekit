# Human Test Checklist: filekit 0.3.0 #15 Phases A+B (link primitives, symlink absorb, V9 fold)

**Target version:** v0.3.0 (dazzle-filekit) + v0.2.2 (unctools, the WNet fold prerequisite)
**Ships with commit:** `v0.3.0 feat: link primitives + symlink absorb + V9 removal (#15 A/B)` (+ unctools `feat: WNetGetUniversalName drive-map enrichment (0.2.2)`)
**Companion automated tests:** `tests/test_link_primitives.py` (16), `tests/test_phase_b_absorb_and_v9.py` (6), `tests/test_import_stability.py` canary (extended); unctools `tests/test_wnet_enrichment.py` (4). Full suites: filekit 321 passed / 10 skipped, unctools 54 passed.

## What this is

A hand-run verification of the Windows filesystem-link behavior the automated suite **mocks or skips**. The unit tests create links *when privileges allow and skip otherwise*, and they mock `win32wnet` so they run anywhere. This checklist exercises the real thing on a real Windows box: actual junction/hardlink/symlink creation, the reparse-buffer target read, the elevation/UAC fallback, the dazzlelink-free symlink path, and the WNet drive-map enrichment against genuinely mapped network/DFS/SUBST drives. Run it on Windows before tagging 0.3.0.

## Prerequisites

1. **Windows 10 1703+ or Windows 11**, Python 3.10+, with `pywin32` installed (`pip show pywin32`). pywin32 powers the win32file symlink API and the win32wnet drive-map scan.
2. **Editable installs** of both libraries from this working tree:
   - filekit: `pip install -e C:\code\filetoolkit\github`
   - unctools: `pip install -e C:\code\unctools\local` (must be **>=0.2.2** for the WNet fold)
   - Verify: `python -c "import dazzle_filekit, unctools; print(dazzle_filekit.__version__, unctools.__version__)"` → `0.3.0 0.2.2...`
3. **Junctions need NO elevation.** **Symlinks DO** need either Developer Mode (Settings → Privacy & security → For developers → Developer Mode = On) or an elevated shell. Note which you have — it determines which symlink method (1 vs 2 vs 4) actually fires.
4. **Optional (Section 6):** at least one **mapped network drive** (`net use Z: \\server\share`), DFS path, or `subst` drive to exercise the WNet enrichment meaningfully.

**State isolation:** all steps use a throwaway scratch dir. Set it once:

- **PowerShell:** `$WORK = "$env:TEMP\fk_links_check"; Remove-Item -Recurse -Force $WORK -ErrorAction SilentlyContinue; New-Item -ItemType Directory $WORK | Out-Null; cd $WORK`
- **cmd.exe:** `set WORK=%TEMP%\fk_links_check & rmdir /s /q "%WORK%" 2>nul & mkdir "%WORK%" & cd /d "%WORK%"`
- **POSIX (WSL/git-bash):** `WORK=/tmp/fk_links_check; rm -rf "$WORK"; mkdir -p "$WORK"; cd "$WORK"`

Reset between sections: `Remove-Item -Recurse -Force $WORK\*` (PowerShell) — never deletes the link *targets* outside `$WORK`.

## High-Value Verification (~5 minutes)

If you only have five minutes, run these. If any fail, the phase is broken.

### HV.1 — Junction round-trips with no elevation

Validates: `create_junction` (PowerShell `New-Item`) + `analyze_link` kind + `read_link_target` (DeviceIoControl reparse buffer).

- [ ] **Steps** (PowerShell, non-elevated):
  ```powershell
  python -c "import os,dazzle_filekit as fk; t=os.path.join(r'$env:TEMP\fk_links_check','tgt'); os.makedirs(t,exist_ok=True); l=os.path.join(r'$env:TEMP\fk_links_check','jct'); print('created:', fk.create_junction(t,l)); i=fk.analyze_link(l); print('kind:', i.kind, 'broken:', i.is_broken); print('target:', fk.read_link_target(l))"
  ```
- [ ] **Expected:** `created: True`, `kind: junction`, `broken: False`, and `target:` ends in `\tgt`.
- [ ] **Why this matters:** junction creation/detection/target-read is the core Phase A surface and must work *without* admin. If this fails, link primitives are unusable.

### HV.2 — Hardlink is valid, not "broken"

Validates: `create_hardlink` + the import-first correctness fix (preservelib marked hardlinks broken; filekit must not).

- [ ] **Steps** (PowerShell):
  ```powershell
  python -c "import os,dazzle_filekit as fk; d=r'$env:TEMP\fk_links_check'; s=os.path.join(d,'f.txt'); open(s,'w').write('x'); l=os.path.join(d,'hard.txt'); print('created:', fk.create_hardlink(s,l)); i=fk.analyze_link(l); print('kind:', i.kind, 'broken:', i.is_broken, 'raw:', i.raw_target)"
  ```
- [ ] **Expected:** `created: True`, `kind: hardlink`, `broken: False`, `raw: None`.
- [ ] **Why this matters:** a hardlink reported as broken would mislead every downstream consumer (preserve, dazzlecmd). This is a deliberate correctness gain over the donor.

### HV.3 — `create_symlink` works with NO dazzlelink installed

Validates: the symlink absorb (win32file/elevation inlined; L1→L2 import cut).

- [ ] **Steps** (PowerShell — Developer Mode or elevated):
  ```powershell
  python -c "import importlib.util as u; print('dazzlelink present:', u.find_spec('dazzlelink') is not None)"
  python -c "import os,dazzle_filekit as fk; d=r'$env:TEMP\fk_links_check'; t=os.path.join(d,'st.txt'); open(t,'w').write('x'); l=os.path.join(d,'slink.txt'); print('created:', fk.create_symlink(t,l)); print('is_symlink:', os.path.islink(l))"
  ```
- [ ] **Expected:** symlink creation returns `True` and `is_symlink: True` **regardless** of whether dazzlelink is present. If `dazzlelink present: False`, you've proven the soft-import was truly cut.
- [ ] **Why this matters:** the whole point of Phase B is that filekit no longer depends on dazzlelink for symlinks. If this only works with dazzlelink installed, the absorb failed.

### HV.4 — `get_drive_mappings` is gone from filekit; capability lives in unctools

Validates: V9 removal + fold.

- [ ] **Steps** (any shell):
  ```
  python -c "import dazzle_filekit.utils.compat as c; print('filekit has get_drive_mappings:', hasattr(c,'get_drive_mappings'))"
  python -c "import unctools; print('unctools.get_mappings:', unctools.get_mappings())"
  ```
- [ ] **Expected:** first line prints `False`; second prints a dict (possibly empty if no mapped drives) without error.
- [ ] **Why this matters:** if filekit still exposes `get_drive_mappings`, the V9 removal didn't happen; if `unctools.get_mappings()` errors, the fold broke L0.

### HV.5 — `compute_relative_path` ≠ `get_relative_path`

Validates: V12 is the new `..`-traversing primitive, not a rename of the subpath-only one.

- [ ] **Steps** (any shell):
  ```
  python -c "from dazzle_filekit import compute_relative_path as c, get_relative_path as g; import os; print('compute:', c(os.path.abspath('a/b/c'), os.path.abspath('a/x'))); print('get:', g(os.path.abspath('a/b/c'), os.path.abspath('a/x')))"
  ```
- [ ] **Expected:** `compute:` prints `..\b\c` (a real relative path); `get:` prints `None` (siblings aren't subpaths).
- [ ] **Why this matters:** a name-match nearly hid that these are different operations. Conflating them would silently break link-relativization.

### HV.6 — Self-referential vs chain cycle

Validates: intrinsic `is_circular` (direct self-ref only).

- [ ] **Steps** (PowerShell — needs symlink privilege):
  ```powershell
  python -c "import os,dazzle_filekit as fk; d=r'$env:TEMP\fk_links_check'; sl=os.path.join(d,'self'); os.symlink(sl,sl); print('self is_circular:', fk.analyze_link(sl).is_circular)"
  ```
- [ ] **Expected:** `self is_circular: True`. (A two-link A↔B chain would report `False` — that's traversal/L3 territory, by design.)
- [ ] **Why this matters:** confirms the intrinsic check is robust to self-loops (doesn't crash on ELOOP) and doesn't overreach into chain detection.

## Section 2: analyze_link matrix (~3 min)

### 2.1 All six cases

- [ ] **Steps** (PowerShell — symlink cases need privilege; junction/hardlink/regular don't):
  ```powershell
  # regular file -> kind None
  python -c "import os,dazzle_filekit as fk; d=r'$env:TEMP\fk_links_check'; p=os.path.join(d,'plain.txt'); open(p,'w').write('x'); print('regular:', fk.analyze_link(p).kind)"
  # nonexistent -> kind None
  python -c "import os,dazzle_filekit as fk; print('missing:', fk.analyze_link(os.path.join(r'$env:TEMP\fk_links_check','nope')).kind)"
  # broken symlink -> kind symlink, is_broken True
  python -c "import os,dazzle_filekit as fk; d=r'$env:TEMP\fk_links_check'; l=os.path.join(d,'broken'); os.symlink(os.path.join(d,'GONE'),l); i=fk.analyze_link(l); print('broken:', i.kind, i.is_broken)"
  ```
- [ ] **Expected:** `regular: None`, `missing: None`, `broken: symlink True`.
- [ ] **Check:** `analyze_link` takes ONLY a link path (no destination arg): `python -c "import inspect,dazzle_filekit as fk; print(list(inspect.signature(fk.analyze_link).parameters))"` → `['link_path']`.

## Section 6: unctools WNet enrichment on REAL drives (~5 min, needs a mapped drive)

> This is the part mocks fundamentally cannot do. Requires a real mapped network drive, DFS path, or `subst` drive.

### 6.1 Enriched mappings include what `net use` shows

- [ ] **Setup:** ensure at least one mapped drive: `net use` (lists SMB) and/or `subst Q: C:\Windows` (a non-network test SUBST).
- [ ] **Steps** (PowerShell):
  ```powershell
  net use
  python -c "import unctools; m=unctools.get_mappings(); print('count:', len(m)); [print(' ', k, '->', v) for k,v in m.items()]"
  ```
- [ ] **Expected:** `get_mappings()` returns a dict whose drives include those `net use` lists; values are normalized (UNC lowercased, no trailing slash → drive `X:\`).
- [ ] **Why this matters:** the fold's purpose is to *add* drives `net use` misses (third-party/DFS providers) while never overwriting authoritative net-use entries. On a plain SMB-only box the set may match `net use`; the value-add shows on machines with non-SMB providers.

### 6.2 Reverse direction

- [ ] **Steps** (PowerShell):
  ```powershell
  python -c "import unctools; print(unctools.get_reverse_mappings())"
  ```
- [ ] **Expected:** a dict keyed by `X:` → UNC; no exception.

## What the automated tests DON'T cover

- **Real junction/hardlink/symlink creation** on NTFS — tests skip when privileges or filesystem support are absent.
- **The PowerShell UAC-elevation fallback** (method 4) — requires a human to accept/cancel the prompt; cannot be asserted.
- **The win32file API path** specifically — tests don't force method 1 to fail, so method 2 may not be exercised on a Developer-Mode box.
- **Reparse-buffer parsing against real junctions** of varied shapes (DFS, volume mount points, `\??\` vs PrintName).
- **WNet provider-chain enrichment on real non-SMB / DFS / SUBST drives** — `win32wnet` is mocked in CI.
- **pywin32-absent behavior** — the graceful "win32file not available → mklink fallback" path on a machine without pywin32.
- **Cross-device EXDEV** hardlink rejection across two real volumes.
- Shell rendering of any logged warnings (Windows codepage).
